# 🔴 HU-012: Desarrollar ProductoService con Principios SOLID

**Sprint:** 5 | **Estimación:** 8 SP | **Prioridad:** Crítica

---

## 📝 Descripción

**Como** desarrollador del sistema,  
**Quiero** crear un servicio de productos que orqueste la lógica de negocio,  
**Para** separar responsabilidades y aplicar principios SOLID.

---

## ✅ Criterios de Aceptación

### Constructor con Inyección de Dependencias

- [ ] Constructor: `public ProductoService(Repositorio<Producto> repositorio)`
- [ ] No instanciar repositorio internamente (DIP - Dependency Inversion Principle)
- [ ] Almacenar en atributo privado `private final Repositorio<Producto> repositorio`

### Métodos CRUD

- [ ] `public Producto crearProducto(TipoProducto tipo, Map<String, Object> datos)`
  - Usa ProductoFactory
  - Valida datos antes de crear
  - Guarda usando repositorio
  - Retorna producto creado
- [ ] `public Optional<Producto> obtenerProducto(int id)`
- [ ] `public List<Producto> listarProductos()`
- [ ] `public List<Producto> listarProductos(Predicate<Producto> filtro)` - Con filtro funcional
- [ ] `public boolean actualizarProducto(int id, Map<String, Object> datos)`
- [ ] `public boolean eliminarProducto(int id)` (soft delete - marcar como inactivo)

### Métodos de Negocio

- [ ] `public List<Producto> buscarPorNombre(String termino)` - Case-insensitive
- [ ] `public List<Producto> productosConStockBajo(int umbral)` - Default umbral = 10
- [ ] `public double calcularValorTotalInventario()` - Suma precio \* stock
- [ ] `public List<Producto> productosPorCategoria(int categoriaId)`
- [ ] `public List<Producto> productosPorTipo(TipoProducto tipo)`

### Validaciones

- [ ] Validar nombres no duplicados al crear (buscar existente)
- [ ] Validar precio positivo
- [ ] Validar stock >= 0
- [ ] Lanzar `IllegalArgumentException` con mensajes descriptivos

### Aplicación de SOLID

- [ ] **S** (Single Responsibility) - Solo lógica de negocio de productos
- [ ] **O** (Open/Closed) - Extensible sin modificar código
- [ ] **L** (Liskov Substitution) - Funciona con cualquier tipo de Producto
- [ ] **I** (Interface Segregation) - Depende de interface Repositorio
- [ ] **D** (Dependency Inversion) - Depende de abstracción, no implementación

### Documentación JavaDoc

- [ ] Documentar clase con propósito y responsabilidades
- [ ] Documentar cada método público con `@param`, `@return`, `@throws`

## 🧪 Ejemplo de Uso

```java
Repositorio<Producto> repo = new ProductoRepositorioJSON("data/productos.json");
ProductoService servicio = new ProductoService(repo);

// Crear producto
Map<String, Object> datos = new HashMap<>();
datos.put("nombre", "Laptop HP");
datos.put("precio", 1299.99);
datos.put("stock", 15);
datos.put("pesoKg", 2.3);
datos.put("dimensiones", "40x30x3 cm");

Producto laptop = servicio.crearProducto(TipoProducto.FISICO, datos);

// Buscar productos con stock bajo
List<Producto> stockBajo = servicio.productosConStockBajo(10);

// Calcular valor del inventario
double valorTotal = servicio.calcularValorTotalInventario();
```
