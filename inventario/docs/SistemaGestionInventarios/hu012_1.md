# 🔴 HU-012: Desarrollar ProductoService con Principios SOLID

**Sprint:** 5 | **Estimación:** 8 SP | **Prioridad:** Crítica

---

## 📝 Descripción

**Como** desarrollador del sistema,  
**Quiero** crear un servicio de productos que orqueste la lógica de negocio,  
**Para** separar responsabilidades y aplicar principios SOLID.

---

## ✅ Criterios de Aceptación

### Constructor con Inyección de Dependencias

- [ ] `__init__(self, repositorio: Repositorio[ProductoBase])`
- [ ] No instanciar repositorio internamente (DIP)

### Métodos CRUD

- [ ] `crear_producto(tipo: TipoProducto, datos: dict) -> ProductoBase`
  - Usa ProductoFactory
  - Valida datos antes de crear
  - Guarda usando repositorio
- [ ] `obtener_producto(id: int) -> Optional[ProductoBase]`
- [ ] `listar_productos(filtro: Optional[dict]) -> List[ProductoBase]`
- [ ] `actualizar_producto(id: int, datos: dict) -> bool`
- [ ] `eliminar_producto(id: int) -> bool` (soft delete)

### Métodos de Negocio

- [ ] `buscar_por_nombre(termino: str)` case-insensitive
- [ ] `productos_con_stock_bajo(umbral: int = 10)`
- [ ] `calcular_valor_total_inventario() -> float`
- [ ] `productos_por_categoria(categoria_id: int)`

### Validaciones

- [ ] Validar nombres no duplicados al crear
- [ ] Validar precio positivo
- [ ] Validar stock >= 0
- [ ] Lanzar excepciones descriptivas

### Aplicación de SOLID

- [ ] **S** - Solo lógica de negocio de productos
- [ ] **O** - Extensible sin modificar código
- [ ] **L** - Funciona con cualquier ProductoBase
- [ ] **I** - Depende de interface Repositorio
- [ ] **D** - Depende de abstracción, no implementación
