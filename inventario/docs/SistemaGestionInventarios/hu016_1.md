# 🟠 HU-016: Escribir Tests Unitarios Completos

**Sprint:** 7 | **Estimación:** 8 SP | **Prioridad:** Alta

---

## 📝 Descripción

**Como** desarrollador del sistema,  
**Quiero** tener cobertura de tests unitarios de al menos 70%,  
**Para** garantizar la calidad y confiabilidad del código.

---

## ✅ Criterios de Aceptación

### Tests para Producto (JUnit 5)

- [ ] Test creación de cada tipo de producto
- [ ] Test `calcularPrecioFinal()` para cada tipo
- [ ] Test validaciones (precio negativo, stock negativo) con `assertThrows`
- [ ] Test métodos específicos (diasParaVencer, generarEnlaceDescarga)
- [ ] Test polimorfismo (lista mixta de productos con `List<Producto>`)

### Tests para Venta

- [ ] Test agregar/eliminar items
- [ ] Test cálculos (subtotal, descuento, total)
- [ ] Test completar venta (verificar estado)
- [ ] Test validaciones con `assertThrows(IllegalArgumentException.class, ...)`
- [ ] Test estado (no modificar venta completada)

### Tests para Repositorios

- [ ] Test CRUD completo
- [ ] Test persistencia (guardar y recuperar)
- [ ] Test búsquedas con diferentes criterios
- [ ] Test con archivo vacío (mock o archivo temporal)
- [ ] Test con JSON corrupto (usar `@TempDir` de JUnit)

### Tests para Estrategias

- [ ] Test cada estrategia de descuento
- [ ] Test validaciones de parámetros
- [ ] Test casos borde (monto 0, porcentaje 100, etc.)

### Tests para Observer

- [ ] Test agregar/eliminar observadores
- [ ] Test notificaciones (verificar que se llamen métodos)
- [ ] Test múltiples observadores reciben notificación
- [ ] Usar Mockito para verificar llamadas

### Configuración Maven

- [ ] Configurar Surefire plugin en `pom.xml`
- [ ] Configurar JaCoCo para coverage:
  ```xml
  <plugin>
      <groupId>org.jacoco</groupId>
      <artifactId>jacoco-maven-plugin</artifactId>
  </plugin>
  ```
- [ ] Meta de coverage >= 70%

### Anotaciones JUnit 5

- [ ] `@Test` - Marcar métodos de test
- [ ] `@BeforeEach` - Setup antes de cada test
- [ ] `@AfterEach` - Cleanup después de cada test
- [ ] `@DisplayName` - Nombres descriptivos para tests
- [ ] `@ParameterizedTest` - Tests parametrizados (opcional)

## 🧪 Ejemplo de Test

```java
@Test
@DisplayName("Crear producto físico válido")
void testCrearProductoFisicoValido() {
    ProductoFisico producto = new ProductoFisico(1, "Laptop", 999.99, 10, 2.0, "40x30x3");

    assertEquals("FISICO", producto.getTipoProducto());
    assertEquals(999.99, producto.getPrecio(), 0.01);
    assertTrue(producto.calcularPrecioFinal() > 999.99); // Incluye envío
}

@Test
@DisplayName("Precio negativo lanza excepción")
void testPrecioNegativoLanzaExcepcion() {
    assertThrows(IllegalArgumentException.class, () -> {
        new ProductoFisico(1, "Test", -10.0, 10, 1.0, "10x10x10");
    });
}

@Test
@DisplayName("Venta completada no permite agregar items")
void testVentaCompletadaNoPermiteItems() {
    Venta venta = new Venta();
    venta.agregarItem(new ItemVenta(1, "Producto", 1, 100.0));
    venta.completarVenta();

    assertThrows(IllegalStateException.class, () -> {
        venta.agregarItem(new ItemVenta(2, "Otro", 1, 50.0));
    });
}
```

## 🎯 Comandos Maven

```bash

# Ejecutar tests con coverage
mvn test jacoco:report

# Ver reporte en: target/site/jacoco/index.html

# Ejecutar solo tests de una clase
mvn test -Dtest=ProductoTest

# Compilar y ejecutar tests
mvn clean test
```
