# 🔴 HU-001: Implementar Clase Categoria con Encapsulamiento

**Sprint:** 1 | **Estimación:** 2 SP | **Prioridad:** Alta

---

## 📝 Descripción

**Como** desarrollador del sistema de inventario,  
**Quiero** crear la clase `Categoria` con encapsulamiento apropiado,  
**Para** representar las categorías de productos de forma simple y eficiente.

---

## ✅ Criterios de Aceptación

### Estructura de la Clase

- [ ] Clase Java con modificador `public`
- [ ] Atributos privados: `private int id`, `private String nombre`, `private String descripcion`, `private boolean activa`
- [ ] El atributo `activa` debe tener valor por defecto `true` en el constructor
- [ ] El atributo `descripcion` debe tener valor por defecto como cadena vacía

### Constructores

- [ ] Constructor completo con todos los parámetros
- [ ] Constructor sobrecargado con valores por defecto para `descripcion` y `activa`
- [ ] Validaciones en el constructor

### Métodos Getters y Setters

- [ ] Implementar getters para todos los atributos
- [ ] Implementar setters con validaciones para `nombre` y `descripcion`
- [ ] Setter de `nombre` valida que no sea vacío

### Métodos Especiales

- [ ] Implementar el método `toString()` que retorne el formato: `"[{id}] {nombre}"`
- [ ] Implementar `equals()` y `hashCode()` basados en el `id`

### Validaciones Básicas

- [ ] El nombre no puede estar vacío o null
- [ ] El id debe ser un entero positivo

### Documentación

- [ ] La clase debe tener JavaDoc descriptivo
- [ ] Cada método público debe documentarse con JavaDoc

---

## 🧪 Casos de Prueba

### Caso Normal

```java
Categoria categoria = new Categoria(1, "Electrónica", "Dispositivos electrónicos", true);
assertEquals("[1] Electrónica", categoria.toString());
assertTrue(categoria.isActiva());
```

### Casos Borde

- [ ] Crear categoría con nombre vacío (debe lanzar `IllegalArgumentException`)
- [ ] Crear categoría con id negativo (debe lanzar `IllegalArgumentException`)
- [ ] Crear categoría sin descripción (debe usar cadena vacía por defecto)
