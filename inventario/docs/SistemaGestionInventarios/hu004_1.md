# 🟠 HU-004: Refactorizar Producto con Properties y Validaciones

**Sprint:** 2 | **Estimación:** 5 SP | **Prioridad:** Alta

---

## 📝 Descripción

**Como** desarrollador del sistema,  
**Quiero** refactorizar la clase `Producto` usando properties con getters y setters,  
**Para** encapsular los datos y garantizar que siempre sean válidos.

---

## ✅ Criterios de Aceptación

### Atributos Privados

- [ ] Convertir `nombre`, `precio` y `stock` a atributos privados (`_nombre`, `_precio`, `_stock`)
- [ ] Los atributos no deben ser accesibles directamente desde fuera de la clase

### Property: nombre

- [ ] Getter que retorna `_nombre`
- [ ] Setter que valida: no puede ser cadena vacía, elimina espacios con `.strip()`
- [ ] Lanza `ValueError` si validación falla

### Property: precio

- [ ] Getter que retorna `_precio`
- [ ] Setter que valida: no negativo, redondea a 2 decimales
- [ ] Lanza `ValueError` si precio es negativo

### Property: stock

- [ ] Getter que retorna `_stock`
- [ ] Setter que valida: no negativo, debe ser entero
- [ ] Lanza `ValueError` si es negativo

### Métodos de Gestión de Stock

- [ ] `reducir_stock(cantidad: int) -> bool` - Verifica stock antes de reducir
- [ ] `aumentar_stock(cantidad: int) -> None` - Valida cantidad positiva

---

## 🧪 Casos de Prueba

### Caso Normal

```python
producto = ProductoConValidacion(nombre="Teclado", precio=50.0, stock=20)
assert producto.nombre == "Teclado"
producto.precio = 45.999
assert producto.precio == 46.0  # Redondeado
assert producto.reducir_stock(5) == True
assert producto.stock == 15
```

### Casos Borde

- [ ] Precio negativo debe lanzar ValueError
- [ ] Stock negativo debe lanzar ValueError
- [ ] Reducir más stock del disponible retorna False
- [ ] Nombre vacío debe lanzar ValueError
