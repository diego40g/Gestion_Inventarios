# 🔴 HU-005: Implementar Jerarquía de Productos con Clase Abstracta

**Sprint:** 2 | **Estimación:** 8 SP | **Prioridad:** Crítica

---

## 📝 Descripción

**Como** desarrollador del sistema,  
**Quiero** crear una jerarquía de productos usando herencia y clases abstractas,  
**Para** modelar diferentes tipos de productos con comportamientos específicos.

---

## ✅ Criterios de Aceptación

### Clase Abstracta ProductoBase

- [ ] Heredar de `ABC` del módulo `abc`
- [ ] Constructor con parámetros: id, nombre, precio, stock
- [ ] Atributos protegidos con prefijo `_`
- [ ] Property abstracta `tipo_producto` con @abstractmethod
- [ ] Método abstracto `calcular_precio_final()`
- [ ] Implementar `__str__()`: `"[{tipo_producto}] {nombre} - ${precio:.2f}"`

### ProductoFisico

- [ ] Heredar de ProductoBase
- [ ] Atributos: `peso_kg: float`, `dimensiones: str`
- [ ] Property `tipo_producto` retorna `"FISICO"`
- [ ] `calcular_precio_final()` incluye costo envío: 5.0 + (peso_kg \* 1.5)
- [ ] Método `calcular_costo_envio(destino: str)`

### ProductoDigital

- [ ] Heredar de ProductoBase
- [ ] No requiere stock (ilimitado)
- [ ] Atributos: `tamaño_mb`, `formato`, `url_descarga`
- [ ] Property `tipo_producto` retorna `"DIGITAL"`
- [ ] `calcular_precio_final()` retorna precio base
- [ ] Método `generar_enlace_descarga()` con token único

### ProductoPerecible

- [ ] Heredar de ProductoBase
- [ ] Atributos: `fecha_vencimiento: date`, `temperatura_conservacion: float`
- [ ] Property `tipo_producto` retorna `"PERECIBLE"`
- [ ] `calcular_precio_final()` aplica descuento progresivo:
  - Más de 30 días: 0% descuento
  - 15-30 días: 10% descuento
  - 7-14 días: 25% descuento
  - Menos de 7 días: 50% descuento
- [ ] Método `esta_vencido()` retorna bool
- [ ] Método `dias_para_vencer()` retorna int

### Uso de super()

- [ ] Todas las subclases llaman a `super().__init__()`
